# Сценарии и план проверки

## Подтверждённый демонстрационный маршрут

1. Сотрудник спрашивает об антикоррупционной политике.
2. Бот выводит ответ с документом и страницей.
3. Следующий вопрос касается повышения зарплаты.
4. В интерфейсе появляется обращение к HR.
5. HR открывает кабинет, переписку и отвечает.
6. Сотрудник получает ответ в MAX.

В ролике также появляется сообщение о технической неудаче. По одной записи нельзя заключить, что передача к HR вызвана исключительно отсутствием данных. Пауза генерации удалена монтажом; ролик не является бенчмарком.

## Приёмочные сценарии

Это план проверок, не отчёт об их выполнении.

| Сценарий | Проверяемый результат |
|---|---|
| Вход сотрудника и HR с одного устройства | Разные полномочия по учётной записи |
| Попытка HR другой площадки открыть обращение | Отказ на стороне API |
| Вопрос во время опроса | Сохранение ответов и позиции |
| Повторный вход в незавершённый опрос | Продолжение без потери прогресса |
| Документ архивирован | Исключение из разрешённых источников |
| Ответ HR | Доставка в нужный диалог и сохранение истории |
| Окончание адаптации | Общие возможности доступны, новые onboarding-шаги ограничены |
| Выгрузка результатов | Соответствие данным и правам пользователя |
| Поручение руководства | Проверка полномочий, статуса и результата |
| Неопределённый результат отправки | Нет слепого автоматического повтора |

## Метрики следующего этапа

- RAG: корректность ответа, релевантность источника, полнота, правильность отказа.
- API: p50/p95 задержки, частота ошибок, пропускная способность.
- ML: время в очереди и время генерации отдельно.
- Продукт: время до первого ответа HR, время решения, доля повторных вопросов.
- Эффект: высвобождённое время при сопоставимом качестве помощи.

В портфолио не указаны неподтверждённые проценты точности, экономии или гарантированная нагрузка.
